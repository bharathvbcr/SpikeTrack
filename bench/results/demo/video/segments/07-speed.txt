The speed comes from Apple's Core ML compiler, not from the language that calls it. So on the last day, we exported the heaviest parts as half-precision Core ML programs, and we call them from Rust. The image encoder and the memory attention cut a frame to about 0.6 of the time it took the day before. The necks, run on the encoder's own thread, took about another tenth off, and the memory encoder about another sixth. Tracking accuracy over 1,500 frames held at each step. It is not real time yet: about one second a frame on dense video, with detection and tracking together. The existing Core ML port of SAM 3.1 is fast for the same reason, but it is only the tracker. It cannot read a text prompt, find objects, or start new tracks. SpikeTrack runs all of SAM 3.1.
