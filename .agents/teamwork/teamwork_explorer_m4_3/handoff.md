## 2. Logic Chain

### 2.1 Exact Mathematical & Algorithmic Equivalence for Milestone 4 Ops

#### 1. `gelu_tanh` Forward & Backward
- **PyTorch Forward Reference**: `torch.nn.functional.gelu(x, approximate='tanh')`
  - Canonical formula:
    $$u = \sqrt{\frac{2}{\pi}} \left(x + 0.044715\, x^3\right)$$
    $$\text{GELU}_{\text{tanh}}(x) = \frac{1}{2} x \left(1 + \tanh(u)\right)$$
  - Numerically stable reformulation in `ojas_core::gelu_tanh_exact`:
    Using $1 + \tanh(u) = 2 \cdot \text{sigmoid}(2u)$, we write:
    $$s = \text{sigmoid}\left(2 \sqrt{\frac{2}{\pi}} \left(x + 0.044715\, x^3\right)\right)$$
    $$\text{GELU}_{\text{tanh}}(x) = x \cdot s$$
    This eliminates catastrophic subtraction cancellation in the negative tail ($x \le -8$), where $1 + \tanh(u)$ subtracts numbers arbitrarily close to 1 in finite precision.
- **PyTorch Backward Reference**: `y.backward(gy)`
  - Derivative:
    $$\frac{d}{dx}\text{GELU}_{\text{tanh}}(x) = s + x \cdot s(1 - s) \cdot 2 \sqrt{\frac{2}{\pi}}\left(1 + 3 \cdot 0.044715\, x^2\right)$$
  - Derivative limits:
    - As $x \to +\infty$: $\frac{d}{dx} \to 1.0$, $\text{dx} \to \text{gy}$.
    - As $x \to -\infty$: $\frac{d}{dx} \to 0.0$, $\text{dx} \to -0.0$.
    - At $x = 0$: $\frac{d}{dx} = 0.5$, $\text{dx} = 0.5 \cdot \text{gy}$.
  - Non-finite boundary: Inputs with NaN or $\pm\infty$ must fail closed with `OjasError::NonFinite` rather than propagating NaN.

#### 2. Symmetric Non-Causal Sliding Window Attention ($|i - j| \le W$)
- **PyTorch / Transformers Reference**:
  In `transformers.models.embedding_gemma2.modeling_embedding_gemma2`:
  - Uses `create_bidirectional_sliding_window_mask` and `eager_attention_forward(scaling=1.0)`.
  - Unlike causal sliding window attention (which only looks backward $t - W < j \le t$), symmetric non-causal sliding window attention allows token $i$ to attend to token $j$ iff:
    $$|i - j| \le W \quad \text{and} \quad j < \text{len}_b$$
  - The valid key range for query row $i$ in sequence $b$ is:
    $$\text{lo} = \max(0, i - W), \quad \text{hi} = \min(\text{len}_b, i + W + 1)$$
  - When $T \le W$, the window spans the entire sequence, making it identical to full bidirectional attention.
  - Queries at or past the key length ($i \ge \text{len}_b$) represent padding and must output exact zeros and log-sum-exp 0.0.
  - Attention scale in EmbeddingGemma 2 is explicitly 1.0 (overriding the default $1/\sqrt{D}$).

#### 3. Masked Sequence Mean Pooling (`seq_mean_forward` / `segment_mean_rows`)
- **PyTorch / sentence-transformers Reference**:
  - `sentence_transformers.models.Pooling(pooling_mode_mean_tokens=True)`:
    $$\text{mean}_b = \frac{\sum_{t=0}^{\text{len}_b - 1} X_{b, t, :}}{\max(1, \text{len}_b)}$$
  - In `ojas-cpu`: `seq_mean_forward(x: &Tensor, key_lens: &Tensor)` performs ascending summation in `f64` per column over the active rows $[0..\min(\text{len}_b, T))$, divided by $\text{len}_b$ in `f64`, and rounded once to `f32`.
  - In `ojas-metal`: Dispatches `ojas_segments_from_lens` on the GPU to build $(b \cdot T, b \cdot T + \min(\text{len}_b, T))$ ranges, followed by tessl's `segment_mean_rows_f32`.
  - Invariant: A sequence with length 0 outputs a row of zeros without division-by-zero errors.

#### 4. L2 Normalization with Matryoshka Dimension Truncation (`l2_normalize_forward`)
- **PyTorch / sentence-transformers Reference**:
  - `sentence_transformers.util.truncate_embeddings(x, d)` followed by `torch.nn.functional.normalize(x, p=2, dim=-1, eps=1e-12)`.
  - Formula for prefix $d \in \{768, 512, 256, 128\}$:
    $$\|x_{:d}\|_2 = \sqrt{\sum_{k=0}^{d-1} x_k^2}$$
    $$y_k = \frac{x_k}{\max(\|x_{:d}\|_2, \epsilon)}, \quad \epsilon = 10^{-12}$$
  - Invariant: For all non-zero vectors, the unit sphere constraint holds:
    $$\left|\|y\|_2 - 1.0\right| \le 1.0 \times 10^{-6}$$
  - Slicing and normalization preserve cosine similarity with the unnormalized prefix:
    $$\cos(x_{:d}, y) \ge 1.0 - 10^{-11}$$

#### 5. Per-Head V RMSNorm (`rms_qkv_norm_forward`)
- **PyTorch / Transformers Reference**:
  - In `transformers.models.embedding_gemma2.modeling_embedding_gemma2`:
    - Query and Key projections are normalized per-head with learned weights:
      $$\text{RMSNorm}(q)_h = \frac{q_h}{\sqrt{\frac{1}{D}\sum_{i=1}^D q_{h, i}^2 + \epsilon}} \odot w_{q, h}$$
    - Value projection is normalized per-head with NO learned weights ($w_v \equiv 1$):
      $$\text{RMSNorm}(v)_h = \frac{v_h}{\sqrt{\frac{1}{D}\sum_{i=1}^D v_{h, i}^2 + \epsilon}}$$
    - Crucial difference from Gemma 1: Learned weights multiply directly ($x \odot w$), NOT as $x \odot (1 + w)$.

#### 6. End-to-End EmbeddingGemma 2 Pipeline Parity
- **PyTorch Reference**: `sentence_transformers.SentenceTransformer("google/embeddinggemma-2")` in fp32 eager mode.
- 24-layer Transformer encoder with mixed sliding window ($W=512$, layers 0–4, 6–10, 12–16, 18–22) and full attention (layers 5, 11, 17, 23).
- Evaluated on the 8 canonical sentences in `tessl/tools/embedgemma2_ref/make_reference.py`, covering short queries, multi-lingual scripts, code, and long documents ($T = 1658 > 2W$).
